# 17. Break report

Findings from trying to break Project Atlas locally (in-process apps, a private Postgres, no live
systems). Newest cycle last. Severity follows the scale used for the exercise: Critical (cross-tenant
access, privilege escalation, secret exposure), High (data loss, business rule bypass), Medium (500s or
hangs on hostile input, silent fail-open settings), Low (hardening gaps), Info (things that held).
Work list: `NEXT.md`.

| # | Sev | Area | Finding | State |
|---|-----|------|---------|-------|
| 1 | Medium | Config | `RATE_LIMIT_WINDOW` was an unchecked string. `abc`, `1 parsec`, an empty value or `0` booted fine and then every business request answered 500 (the limiter threw per request). A negative value (`-5 minutes`) and a bare number (`60`, read as 60 ms) booted fine and limited nothing. The same held for `PRIVACY_RATE_LIMIT_WINDOW`. | Fixed: both are validated at boot (`rateLimitWindowSchema`, one second to seven days, `<number> <unit>` only). Tests in `packages/config/test`. |
| 2 | Info | Rate limit | The limiter's in-memory store is a 5,000-entry LRU, so many unique clients cannot grow memory without bound. | Held. |
| 3 | Low | Rate limit | Clients are told apart by `request.ip` with `trustProxy: true`. That is the first `X-Forwarded-For` entry, which a client chooses unless the edge overwrites the header. Vercel does overwrite it, so the launch deployment is not affected; behind a proxy that only appends, one client could pick fresh buckets at will, or push others' buckets out of the LRU. | Accepted for launch, documented in `registerRateLimitedRoutes`. Revisit if the API ever moves behind another proxy. |
| 4 | Medium | Config | `CORS_ORIGINS` entries were not checked. `https://app.example.com/` (trailing slash), `app.example.com` (no scheme), a URL with a path, or `null` started the service fine and then matched no browser `Origin`, so every browser call failed with a CORS error and nothing in the logs said why. | Fixed: a trailing slash and upper-case are forgiven (normalized to the exact origin form), and an entry that can never match stops the boot with the entry named. Tests in `packages/config/test/cors-origins.test.ts`. |
| 5 | Low | Config | `CORS_ORIGINS=*` is accepted in production although `docs/16` says never to use it and the config comment says development only. The API authenticates with bearer tokens, not cookies, so a wildcard does not expose a session, but the rule is not enforced. | Open: needs an owner decision, because the live preview may rely on `*` (see `NEXT.md`, "Needs Nikshey"). |
| 6 | Medium | Auth | When the Supabase key set (JWKS) could not be fetched or read (project paused, network failure, 5xx, a page that is not a key set), token verification answered **401 on every request**. The web app treats a 401 as "this session is dead" and signs the user out, so a short outage or a paused project logged everyone out instead of showing "try again". | Fixed: key-set failures now answer 503 `UPSTREAM_UNAVAILABLE`; a bad token on a healthy key set is still 401. Tests in `packages/auth-kit/test/tokens-attacks.test.ts`. |
| 7 | Low | Auth | `jwtVerify` was called without required claims, and jose treats a missing `exp` as a token that never expires. Exploiting it needs a validly signed token, which Supabase never issues without `exp`, so this is hardening. | Fixed: `exp` and `sub` are required. |
| 8 | Medium | Jobs ingestion | A job board that put a NUL byte (`\u0000`) in any title, location or description made Postgres refuse that posting, so it was counted as rejected. Any rejected posting makes the run skip the sweep that deactivates closed roles, so one such posting kept every stale posting of that board active and recommended for as long as the board listed it. The same fields also stored other control characters (BEL, ESC) and bidirectional overrides (U+202E), which garble logs and can make a title read as something else. | Fixed: every posting text field is stripped of NUL, control characters (except tab, line feed, carriage return) and bidi overrides/isolates before it is stored (`stripUnsafeChars` in `job-sources/common.ts`). Tests: `services/jobs/test/hostile-postings.test.ts` (fails without the fix), `job-source-mappers.test.ts`. |
| 9 | High | Profile / ai | `parseResumeText` used an email pattern with open-ended quantifiers (`[a-zA-Z0-9._%+-]+@...`). On a run of local-part characters with no `@` (a resume that is one long word, or `aaaa...`, `----...`, `1111...`, `2020-2020-...`) it rescanned from every start position: quadratic time. A 200,000-character `text/plain` upload (the extraction cap) kept the function busy for minutes, far past the 30 s limit, and the parse runs inside the upload request. One authenticated request could pin an instance; 20 uploads a minute per address could pin many. It also affected `POST /v1/resumes/:id/optimize` and anything else that parses resume text. Found when the first sweep hung the test run for over six minutes. | Fixed: the local part, domain and top-level domain are bounded (64, 255, 24). The parse of any 200,000-character shape in the sweep now takes under 100 ms. New `packages/ai/test/adversarial-input.test.ts` checks growth on 37 hostile shapes at two sizes (it fails in under two minutes against the old pattern instead of hanging). |

## What was checked and held

- `vercel.json`: every `/v1/...` and `/internal/<service>/...` route that each deployed service declares resolves to that service's function, every rewrite destination has a bundle and a function entry, and the service-local `/internal/drain`, `/health` and `/metrics` are not routed at all. New test `packages/utils/test/vercel-routing.test.ts` (it fails when a rewrite is removed).
- Drain and ingest secret checks (`isAuthorizedDrainRequest`): hashed and compared in constant time, no length oracle, empty secret never matches, a duplicate `Authorization` header (joined with a comma by Node) is refused, a secret containing spaces fails closed.
- Token forgery (new `tokens-attacks.test.ts`, all refused with 401): `alg: none` (with, without and with a junk signature), HS256 signed with the public key as secret (PEM, JWK JSON and raw coordinates), a token signed by another key under the right, an unknown or no `kid`, an embedded `jwk` header, `jku` and `x5u` pointing at an attacker, a payload swapped under a valid signature, wrong issuer (including a trailing slash), wrong or missing audience (string and array), `nbf` in the future, junk and 1 MB tokens, a missing or non-uuid `sub`, an unknown role, a non-uuid organization, and role or organization supplied through `user_metadata` or the top level of the token (ignored).
- Ownership checks read: resumes, messages, applications (owner or same-organization admin/owner, 404 otherwise), recommendations (own, or a member of the caller's organization), contacts (a company's contacts only to someone who applied there), learning metrics and job ingest/sources (platform admins only). All answer 404 for what the caller may not see.
- Job-board reading: the request URL is the provider's fixed origin plus a token checked against a pattern (and checked again after the URL is built); redirects are refused; the response is capped at 25 MB by header and by streamed size; the deadline holds even for a `fetch` that ignores the abort signal; error text stored on the source is fixed, never copied from the response. Hostile postings ingested end to end against Postgres: `javascript:` and `data:` apply links are stored as no link, markup in a title is kept as text, a 100 KB title and a 500 KB description are cut to 300 and 200,000 characters, entries with no id or the wrong shape are skipped without failing the board.
- The other parsing regexes in `packages/ai` (phone, URL, month/year, date ranges, section headers, bullet and keyword matching) and `extractSkillKeywords`/`analyzeResumeForJob` grow linearly on the same 37 shapes, including a keyword that is itself a pattern (`(a+)+$`), which is escaped and matched as text.
- `RATE_LIMIT_MAX` of 0 is refused at boot (`min(1)`).
- `/health`, `/metrics` and `/internal/*` are exempt because they are registered outside the limited scope, not by path matching, so no path trick can move a business route into the exempt set.
